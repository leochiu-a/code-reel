Create `src/app/opengraph-image.tsx`:

```tsx
import { ImageResponse } from "next/og";

export const size = {
  width: 1200,
  height: 630,
};

export const contentType = "image/png";

export default function Image() {
  return new ImageResponse(
    (
      <div
        style={{
          width: "100%",
          height: "100%",
          display: "flex",
          flexDirection: "column",
          alignItems: "center",
          justifyContent: "center",
          backgroundColor: "#181818",
          padding: "80px",
        }}
      >
        <div
          style={{
            fontSize: 96,
            fontWeight: 700,
            color: "#ffffff",
            letterSpacing: "-2px",
            lineHeight: 1,
            marginBottom: 24,
          }}
        >
          CodeReel
        </div>
        <div
          style={{
            fontSize: 36,
            fontWeight: 400,
            color: "rgba(255, 255, 255, 0.6)",
            letterSpacing: "-0.5px",
            textAlign: "center",
          }}
        >
          Animate your code. Share your story.
        </div>
      </div>
    ),
    {
      ...size,
    },
  );
}
```

Key implementation notes:
- No font loading required — satori (used internally by ImageResponse) handles system sans-serif fonts adequately for this minimal design. Inter loading via fetch adds complexity without meaningful visual benefit at this size.
- All styles must use the `style` prop with React inline style objects — Tailwind CSS does NOT work inside ImageResponse JSX.
- The `size` named export (width: 1200, height: 630) is required by Next.js to generate correct `og:image:width` and `og:image:height` meta tags.
- The `contentType = "image/png"` named export tells Next.js the MIME type.
- Next.js auto-discovers this file and injects `<meta property="og:image" content="https://codereel.dev/opengraph-image">` in the layout's `<head>` (because `metadataBase` is set in layout.tsx).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ImageResponse JSX → PNG output | Server-side image generation; no user input in scope |
| og:image URL → social scrapers | Public URL; static image content; no auth required |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Injection | ImageResponse JSX content | accept | All text content ("CodeReel", tagline) is hardcoded in source code. No user input or request data flows into the image JSX. Zero injection surface. |
| T-03-02 | Denial of Service | /opengraph-image endpoint | accept | Next.js caches ImageResponse output after first render. Subsequent requests serve the cached PNG. No per-request computation cost after first hit. Acceptable for a public marketing page. |
| T-03-03 | Information Disclosure | OG image content | accept | Image shows only public brand content — name and tagline. No internal details, user data, or server information leaked. |
</threat_model>
