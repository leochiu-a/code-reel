<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sitemap.ts → XML output | Hardcoded URLs only; no request data |
| robots.ts → text output | Hardcoded directives; no request data |
| layout.tsx metadata → HTML head | Static metadata object; no user input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Injection | sitemap.ts URL values | accept | URLs are hardcoded string literals (`"https://codereel.dev/"`). No user input or env interpolation. Cannot be tampered with at runtime. Low risk. |
| T-02-02 | Injection | metadata OG/Twitter fields | accept | All metadata values are static string literals in source code. No user-supplied content flows into meta tags. Next.js escapes metadata values during HTML rendering. |
| T-02-03 | Information Disclosure | robots.txt Allow: / | accept | Explicitly allowing all routes is intentional per SPEC.md. The /app editor is a public tool. No admin routes or sensitive paths exist that need protection at robots.txt level. |
| T-02-04 | Spoofing | canonical URL | accept | Canonical points to the production domain. Hardcoded — cannot be overridden by request manipulation. Canonical is advisory for crawlers, not a security control. |
</threat_model>
